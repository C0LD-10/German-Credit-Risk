# German Credit Risk — A Methodology-First Project

A credit-risk analysis and scoring project built around one governing principle:
**evidence over convenience.** The project discovers early that its source data has
no ground-truth default label, and rather than quietly working around that (the way
most notebooks built on this dataset do), it makes that constraint the center of the
analysis — and still delivers a complete, production-shaped, leakage-safe scoring
pipeline, ready to be re-pointed at a real label with a one-line config change.

---

## ⚠️ Read this first: the target-variable caveat

The supplied `data/raw/german_credit_data.csv` is the **9-attribute reduced
redistribution** of the UCI Statlog German Credit dataset. It contains applicant
demographics, account status, and loan terms — but **no default/repayment outcome
column.** It is not the 20-attribute, labeled original.

Consequently:

- Everything in **Sections 1–12** of the notebook (data quality, missingness
  mechanism, distributions, correlations, feature engineering) is standard, fully
  valid analysis — no caveat needed.
- **Section 13** (unsupervised segmentation) is the only label-free technique that
  can honestly describe "risk structure" in this data.
- **Sections 14–17** (proxy scoring, supervised modeling, cost-sensitive
  thresholding) are a **methodology demonstration** on a transparent, documented
  heuristic target (`proxy_high_risk`), built only to validate that the engineering
  pipeline — leakage prevention, cross-validation, calibration, cost-sensitive
  decisioning — is correct. The reported ~0.99 ROC-AUC is **expected circularity**
  (the model recovers a formula this project wrote down), not real-world predictive
  power, and must never be quoted as such.

See `config.yaml` → `target.mode` and `src/proxy_scoring.py` for exactly where this
is implemented, and `reports/pipeline_run_report.md` (generated by each pipeline
run) for a report that restates this caveat at the top.

**The moment a real label is available:** set `target.mode: "real_label"` and
`target.label_column: "<your column>"` in `config.yaml`. No other code changes are
required — `src/proxy_scoring.get_target()` is the single switch point every
downstream module reads from.

## Setup

```bash
python -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
```

## Running the pipeline

```bash
python -m src.pipeline                 # uses config.yaml in the project root
python -m src.pipeline --config custom_config.yaml   # or an override
```

This runs, in order: schema-validated load → missing-data diagnosis & treatment →
feature engineering → unsupervised segmentation → target construction → model
comparison (5-fold stratified CV) → final model training → held-out evaluation →
fairness audit → cost-sensitive threshold optimization, then writes:

- `models/best_model.joblib` + `models/feature_metadata.json`
- `data/processed/processed_applicants.parquet`
- `reports/pipeline_run_report.md` and `reports/figures/*.png`

Each run logs its key decisions and results to stdout.

## Running the tests

```bash
pytest tests/ -v
```

Covers schema validation, the missing-data treatment decision, feature-engineering
determinism (specifically guarding against train/serve skew between the batch
pipeline and the single-applicant app path), and the proxy score's invariants
(weights sum to 1, bounded output, `Sex` never used as an input).

## Running the scoring app

```bash
streamlit run app/app.py
```

Loads the model trained by `src/pipeline.py` and scores a single applicant entered
through a form, reusing `src.features.engineer_features` directly (not a
reimplementation) so the app can never silently drift out of sync with how the
model was trained. The app prominently repeats the proxy-target caveat.

## Exploring the full analysis

Open `notebooks/01_eda_and_methodology.ipynb` — a fully executed, 18-section
notebook with the complete narrative: data quality audit, a formal missingness-
mechanism test (Mann-Whitney U / Chi-square, used to justify treating "no account"
as an explicit category rather than imputing it away), univariate/bivariate/
correlation analysis, feature engineering rationale, unsupervised segmentation,
the proxy scoring methodology, model comparison, cost-sensitive decisioning, a
fairness audit, and a Limitations/Future Work section that separates observations,
analysis, conclusions, and limitations explicitly.

## Design decisions worth knowing about

- **Missing-data treatment.** `Saving accounts` (18.3% missing) and
  `Checking account` (39.4% missing) are encoded as an explicit `"none"` category,
  not mode-imputed. This is justified by a formal missingness-association test
  (`src/preprocessing.missingness_association_test`) showing missingness correlates
  with other observed variables — inconsistent with pure MCAR — combined with the
  domain-standard "no account held" interpretation. This remains a **documented
  assumption**, flagged for confirmation against the source system (see
  Limitations).
- **Feature engineering is a single deterministic function**
  (`src/features.engineer_features`), called identically by the training pipeline
  and the scoring app, with the long-duration quantile threshold passed explicitly
  at inference time rather than recomputed — the most common source of train/serve
  skew bugs in small ML demos, and the subject of a dedicated regression test.
- **`Sex` is excluded from every model feature** (protected attribute), but still
  audited post-hoc (`src/fairness.py`) for disparate impact via correlated
  features — exclusion from inputs does not guarantee a fair outcome.
- **Cost-sensitive thresholding** uses the 5:1 false-negative:false-positive ratio
  widely cited in credit-scoring literature alongside this dataset family. This is
  illustrative of the *mechanism*; a real deployment should replace it with a cost
  matrix derived from actual loss-given-default and cost-of-capital figures.

## Limitations

1. **No ground-truth label** — the central limitation. Every "risk" statement
   under the proxy target is either descriptive (clustering) or explicitly
   conditioned on a heuristic, not an empirical claim about default probability.
2. **Proxy score circularity** — its weights are judgment calls, documented but
   not fit to any outcome; strong reported metrics are expected, not evidence of
   quality.
3. **Small, single-snapshot sample** (n=1,000, no timestamps) — no ability to test
   temporal drift or macroeconomic sensitivity.
4. **Missingness interpretation unverified** against the data owner.
5. **Fairness audit is preliminary** — one attribute, one audit slice; not a
   substitute for a full disparate-impact study.

## Future work

1. Obtain a true label (join the full 20-attribute Statlog dataset, or acquire real
   repayment outcomes) and flip `config.yaml: target.mode` to `"real_label"`.
2. Replace the illustrative 5:1 cost ratio with a cost matrix derived from real
   financial figures.
3. Confirm the missing-data treatment with the data owner.
4. Extend the fairness audit to intersectional groups and formal parity metrics.
5. Add temporal/macroeconomic features if a dated version of the data becomes
   available.
